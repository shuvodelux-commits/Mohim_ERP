## 1. Verified source bug

`Reports.gs:computeProfit_` calculates the sale-period Cost of Goods Sold directly from `SALE_ITEM_LOTS.Quantity × Unit Cost`. This is the source-faithful *provisional* unit cost at the time of an OVERSOLD sale, per the owner-approved rule: use the **last real purchased lot cost when the sale is made**. The native purchase settlement writer introduced in PR #63 creates immutable `STOCK_LOT_SETTLEMENTS` rows carrying each original invoice, original oversold lot, new purchase lot, quantity ticks, provisional versus actual cost in paisa, and signed favorable variance. **Before this task, the Profit report ignored those events entirely**, so it still showed original provisional COGS even after the real new purchase funded the old sale.

## 2. Source-specific implementation

- New `ProfitOversoldCosts.gs:computeCommittedOversoldCostOverlay_` is a **pure read-only source reconciler**. It correlates each committed immutable settlement event with a uniquely matched `PURCHASE_SETTLEMENT_JOURNAL` receipt; verifies the actual PURCHASE ID/discount, original `SALE_ITEM_LOTS` invoice/product/lot/source product and provisional unit cost, genuine old `OVERSOLD` stock lot and current negative/consumed amount, new positive purchased lot and its actual unit cost. It validates identity uniqueness, 6-decimal base-unit quantity ticks, source conservation and event-level exact paisa COGS/variance with integer arithmetic. No invoice, sale item, stock, journal, profit row, payment or customer balance is overwritten.
- A **missing committed source allocation** is not accepted as zero delta: each OVERSOLD sale source with sale quantity remaining must reconcile **net returned sale units = funded units + still-negative source lot units**. If a committed event disappears or is malformed, a source lot is duplicated, cost/quantity disagrees, the settlement journal is Writing/Needs Review, or source cost is unpriced, the overlay returns `NEEDS_REVIEW`.
- **Source unit costs follow the approved policy:** `SALE_ITEM_LOTS.Unit Cost` remains the original sale-time provisional last-purchase price; real replenishment cost comes only from the **specific actual new purchase lot**. Effective sale COGS = provisional COGS plus **(actual COGS − provisional COGS)** for each truly committed funded quantity. If 231 Foot sold at provisional ৳68 is funded by 240 Foot bought @৳64.75, the linked sale COGS improves by **৳750.75**, leaving 9 owned Foot. This is a synthetic acceptance fixture, not a claim about the live workbook.
- **Partial funding** is supported: 100 Foot funded at one actual purchase price followed by another purchase at a different price retains each source-specific price and signed variance separately. If an old OVERSOLD source still has negative unfilled stock, `costReconciliation.status` reports **`PROVISIONAL`** with its source count. It never labels the entire amount finalized while units remain unfunded.
- **Purchase-level discounts are unresolved accounting policy:** if a purchase with committed OVERSOLD funding has a nonzero invoice discount, the report **fails closed** with a Needs Review message instead of silently claiming the gross line purchase cost is final. The owner/accountant must approve allocation of discounts to funded quantities and historical profit before production activation.
- `loadCommittedOversoldCostOverlay_` checks whether **both** pre-existing journal sheets exist using direct `getSpreadsheet_().getSheetByName` and validates their actual headers. Do **not** call `Database.gs:getSheet_` merely to inspect presence: that helper **creates missing Sheets**, making a nominal profit report unexpectedly mutate the workbook. Missing both new sheets on an original legacy workbook preserves the original profit behavior; missing only one fails closed. With both existing, reads only real source sheets.
- `Reports.gs:computeProfit_` adds the exact signed paisa delta **to COGS**, product-line cost and original invoice period. It consequently adjusts gross profit and net profit exactly once, preserving the current return-income discount factor, Sales Return net-cost logic, vendor sourcing cost, expense periods and customer/supplier settlement discount handling.
- `Database.gs:invalidateDerivedCachesForSheet_` now advances the profit generation on writes to `STOCK_LOT_SETTLEMENTS` **and** `PURCHASE_SETTLEMENT_JOURNAL`; the previous cache generation list omitted both, risking a stale profit response after newly committed source costs. The new profit computation also uses a versioned cache namespace so a previous deployment's cached provisional profit cannot masquerade as a freshly reconciled result.
- `reports.html` shows a KISS bilingual profit reconciliation card when a period has verified actual-cost adjustments or still-provisional OVERSOLD sources. It hides the extra card on unadjusted, ordinary profit reports. If the source is unsafe the entire Profit report endpoint fails with Needs Review, rather than displaying an authoritative but false number.
